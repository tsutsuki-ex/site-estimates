## 2. 推定システム構成

セラピスト管理を中核に、口コミ・写メ日記を大量の個別ページとして自動生成する仕組み、料金シミュレーターによる見積もり導線、そして会員（マイページ）による認証基盤が特徴的な構成です。

**フロントエンド層**
- 公開サイト（Web / SP）— トップ・予約導線・プロフィール・日記・口コミのSSR/SSGレンダリング、SEOメタ管理
- 会員マイページ（要ログイン）— ログイン・新規登録・パスワード変更画面
- 管理画面（バックオフィス）— セラピスト・予約・日記・口コミ・会員・お知らせの運用管理UI

**アプリケーション層 — 機能モジュール**

| # | モジュール | 説明 |
|---|---|---|
| ① | セラピスト管理 | 49名分のプロフィール・写真・稼働ステータスのCRUD |
| ② | 予約導線・料金シミュレーター | コース×オプション×時間の動的料金計算、WEB予約フォーム |
| ③ | 写メ日記システム | 投稿・個別ページ自動生成・セラピスト別アーカイブ（計200ページ） |
| ④ | 口コミシステム | 投稿フォーム・個別ページ自動生成・モデレーション（計135ページ） |
| ⑤ | 出勤・ランキング集計 | 出勤スケジュール管理、ポイント/リピート/新人等の集計バッチ |
| ⑥ | 会員（マイページ）認証 | ログイン・会員登録・パスワード管理、セッション/認証基盤 |
| ⑦ | キャンペーン・トピックスCMS | 簡易お知らせ管理（一覧＋詳細、計8ページ） |
| ⑧ | 採用エントリー | 求人ページ・応募導線 |
| ⑨ | 外部連携 | アクセス解析、問い合わせ／予約通知（詳細要件は要確認） |

**データ・インフラ層**
- RDB — セラピスト・予約・口コミ・日記・会員などのマスタデータ
- 認証基盤 — 会員パスワードのハッシュ管理、セッション/トークン発行
- 画像/CDN — 写メ日記・プロフィール画像の配信最適化

## 4. 前提条件・スコープ外

### 見積もりの前提
- URL・タイトル・見出し構造から機能を逆引きした概算であり、実際の内部仕様（会員機能の用途、口コミ投稿の承認フロー、決済有無等）は未確認です。
- セラピスト49名・口コミ詳細133件・日記詳細75件（＋セラピスト別アーカイブ124件）は今回クロールした実件数です。件数はテンプレート単価に影響しませんが、初期データ移行がある場合は別途工数が発生します。
- チーム体制はPM1名・デザイナー1名・フロントエンド2名・バックエンド2名・QA1名（計7名）を想定。

### スコープ外（別途見積）
- オンライン決済機能（本業態では来店時現金決済が一般的なため未算入）
- プロフィール写真・日記コンテンツの撮影／制作費
- 広告運用・集客施策、既存データ（口コミ・日記・会員情報）の移行作業
- 公開後の月次保守・運用（上表の参考値を目安に別途契約）
